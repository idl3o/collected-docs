## 🎯 **CPHL (CodePrompt Hyper Language)**

### **Document Structure**

CPHL documents follow a consciousness-aware structure:

```
@context[domain=<domain>, framework=<framework>]
@intent[<primary objective>]
@constraints[
  - <requirement 1>
  - <requirement 2>
  - <requirement 3>
]
@examples[
  <code examples>
]
@patterns[
  <reusable patterns>
]
@expansion[<infinite horizon points>]
@synthesis[<combination instructions>]
@reflection[<quality considerations>]
```

### **Section Types**

| Section | Purpose | Example |
|---------|---------|---------|
| `@context` | Set coding environment and domain | `@context[domain=web, framework=React, type=SPA]` |
| `@intent` | Define primary coding objective | `@intent[Create responsive user dashboard with charts]` |
| `@constraints` | Specify requirements and limitations | `@constraints[- TypeScript only - Mobile-first - Accessibility compliant]` |
| `@examples` | Provide code samples and references | `@examples[const Dashboard = () => <div>...</div>]` |
| `@patterns` | Define reusable design patterns | `@patterns[component-pattern: function + hooks + props]` |
| `@expansion` | Connect to infinite horizon points | `@expansion[performance-optimization, real-time-features]` |
| `@synthesis` | Combine multiple concepts | `@synthesis[dashboard + real-time + responsive + accessible]` |
| `@reflection` | Quality and improvement considerations | `@reflection[Consider performance impact, test coverage, maintainability]` |

### **Pattern Templates**

#### **create-component**
**Parameters:** domain, framework, componentType, name, examples  
**Usage:** Component creation with best practices  
**Example:**
```
@context[domain=web, framework=React]
@intent[Create a functional component named UserCard]
@constraints[
  - Use React best practices
  - Include TypeScript types
  - Add proper error handling
  - Follow accessibility guidelines
]
```

#### **api-design**
**Parameters:** apiType, purpose, auth, resourcePattern  
**Usage:** RESTful API architecture  
**Example:**
```
@context[domain=backend, type=REST API]
@intent[Design REST API for user management]
@constraints[
  - RESTful design principles
  - JWT authentication
  - Rate limiting
  - OpenAPI documentation
]
```

#### **database-schema**
**Parameters:** dbType, purpose, normalization, namingConvention, relationshipTypes  
**Usage:** Database design and optimization  
**Example:**
```
@context[domain=database, type=PostgreSQL]
@intent[Design schema for e-commerce platform]
@constraints[
  - Third normal form
  - Performance optimized
  - ACID compliance
]
```

### **Template Variables**

Use handlebars-style variables in patterns:

| Variable | Description | Example |
|----------|-------------|---------|
| `{{name}}` | Component/entity name | `{{name}}` → `UserProfile` |
| `{{framework}}` | Technology framework | `{{framework}}` → `React` |
| `{{domain}}` | Application domain | `{{domain}}` → `web` |
| `{{#if condition}}` | Conditional blocks | `{{#if examples}}{{examples}}{{/if}}` |
| `{{examples}}` | Code examples | User-provided sample code |
