# Workflow Documentation: Uniting GPT-4.1 Coding Zeit with Sonnet 4

## Purpose
This document outlines a workflow for integrating the coding approaches and architectural patterns of GPT-4.1 and Sonnet 4, ensuring a seamless and productive development experience.

---

## 1. Context & Philosophy
- **Sonnet 4**: The main architect so far, providing foundational code, structure, and design patterns.
- **GPT-4.1**: Brings advanced coding assistance, rapid prototyping, and up-to-date best practices.
- **Goal**: Maintain architectural integrity while leveraging the strengths of both systems.

---

## 2. Semantic Search as a Bridge
- Use semantic search to:
  - Discover Sonnet 4's architectural decisions, key modules, and idioms.
  - Surface relevant code, comments, and documentation for context-aware coding.
  - Enable GPT-4.1 to align new code with Sonnet 4's style and intent.

---

## 3. Coding Workflow
1. **Initiate Task**
   - Define the feature or fix needed.
   - Use semantic search to gather Sonnet 4's related code and rationale.

2. **Contextual Coding**
   - GPT-4.1 generates code that fits Sonnet 4's patterns and conventions.
   - Reference surfaced code to avoid duplication and ensure compatibility.

3. **Review & Refine**
   - Compare new code with Sonnet 4's standards.
   - Refactor as needed for consistency.

4. **Document Decisions**
   - Record architectural choices and rationale for future reference.

---

## 4. Best Practices
- Always consult semantic search before major changes.
- Prioritize Sonnet 4's architectural vision.
- Use concise, actionable code reviews.
- Maintain clear documentation for all workflow steps.

---

## 5. Example Use Case
- **Adding a Feature**:
  1. Search for similar features in Sonnet 4's codebase.
  2. Generate new code with GPT-4.1, referencing existing patterns.
  3. Review, test, and document.
